# どんなプロジェクトに向いているか

パーツの中身を何度も変更したり、別の実装に取り替えたりするプロジェクトに向いている。

## 向いている場合

- **長期間開発・保守するアプリケーション**：一部の機能だけを作り直しやすい。
- **計算方法や処理手順を試すシステム**：呼び出し方を変えずに、中身や結果を変更しやすい。
- **外部サービスと連携するシステム**：接続するための処理を一つのパーツにまとめ、切り替え時の修正を減らしやすい。

## 向いていない場合

- **一度使って終わる小さなプログラム**：パーツに分ける手間が、組み換えの利点を上回りやすい。
- **多くの機能が互いの内部処理を直接呼び、まとめるのが難しいシステム**：変更の影響を一部に閉じ込めにくい。
- **入出力の形を頻繁に変えるシステム**：呼び出し元を修正せずに取り替える利点を得にくい。

向いているかどうかは、どこを取り替えたいか、どこまでを一つのパーツにできるか、分割する手間が見合うかで判断する。
