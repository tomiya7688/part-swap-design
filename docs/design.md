# 設計の考え方

## 目的

呼び出し元は、呼び出し先の中身を知らなくても使えるようにする。呼び出し先を取り替えるとき、ほかの部分の修正をできるだけ減らす。

## 閉じた呼び出し関係

```text
a
└── a1
    ├── a1-1
    ├── a1-2
    └── a1-3
```

a1 が a からしか呼ばれず、a1-1 なども a1 の外から直接呼ばれないとする。この場合、a1 以下を一つのパーツとして取り替えられる。このように、呼び出しが特定の範囲に収まっている状態を「閉じた呼び出し関係」と呼ぶ。

ここでいうパーツは、一つのモジュールでも、複数の処理をまとめたものでもよい。

a1 の内部で処理同士が複雑に依存していても、a1 全体は取り替えられる。ただし、a1-1 だけを独立して取り替えられるとは限らない。内部の依存関係が複雑なほど、変更には手間がかかる。

## 開いた呼び出し関係

複数の機能が同じ処理を直接呼んでいると、その処理を変更するときに複数の呼び出し元を考慮する必要がある。

こうした関係はできるだけ避ける。必要なら、呼び出し元とその処理を一つの機能内にまとめ、外からはその機能を通して使うようにする。

## 入出力とテスト

パーツの中身を取り替えても、入力と出力の形が同じなら、呼び出し元の呼び出し方は変えずに済む。**処理の結果まで同じにする必要はない。**

パーツの入口から動作を確かめるテストも、内部構造が変わっただけなら、同じ方法で実行できる。結果の仕様を変えた場合は、テストの期待値もそれに合わせて変える。

## 組み換え単位とコスト

a1 の内部にも閉じた呼び出し関係を作れば、もっと小さな単位で取り替えられる。

ただし、細かく分けるほど管理の手間も増える。組み換えやすさと、分割・変更にかかるコストの両方を考えて決める。
