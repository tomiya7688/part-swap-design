# パーツ組み換え設計 (Part Swap Design)

パーツの内部を変更・交換するときに、ほかのパーツへの影響をできるだけ小さくするための設計の考え方。具体的な実装方法は規定しない。

## 閉じた呼び出し関係

```text
a
└── a1
    ├── a1-1
    ├── a1-2
    └── a1-3
```

a1 が a からしか呼ばれず、a1-1 なども a1 の外から直接呼ばれないなら、a1 以下を一つのパーツとして扱える。このように、外部からの呼び出し口が限られた関係を、ここでは「閉じた呼び出し関係」と呼ぶ。

a1 の内部が複雑でも、a1 全体を交換できる。ただし、a1-1 だけを独立して交換できるとは限らず、内部の依存関係は交換コストになる。

## 設計方針

- 呼び出し元は、呼び出し先の内部構造ではなく、入出力の契約にだけ依存する。
- 複数の場所から呼ばれる処理は、可能な限り一つの機能内に収める。その機能自体は、上位から見て閉じた呼び出し関係にする。
- 閉じたパーツを可能な範囲で小さくし、交換時に扱う依存関係を減らす。ただし、分割自体のコストも考慮する。

## 組み換えとテスト

入出力の契約（結果・エラー・副作用など）を維持すれば、呼び出し元を変更せずにパーツを交換できる。契約を検証するテストも、内部の実装変更に合わせて書き換える必要がない。

この考え方と両立しない設計に、無理に適用することは想定しない。
