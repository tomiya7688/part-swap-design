# パーツ組み換え設計 (Part Swap Design)

パーツの**組み換えやすさ**を目的とし、変更の影響範囲を閉じた呼び出し関係に限定する設計原則。特定の言語や実装手法は規定しない。

## 原則

- 呼び出し元は呼び出し先の内部構造に依存せず、外部との契約だけを知る。
- パーツの単位はモジュール、または呼び出し関係が閉じた処理群とする。
- 開いた呼び出し関係は可能な限り避ける。必要なら特定の機能内に閉じ込め、その機能自体を上位から見て閉じたパーツにする。
- 閉じた単位を可能な範囲で小さくし、組み換えに必要な変更を減らす。

## 組み換え単位

```text
a
└── a1
    ├── a1-1
    ├── a1-2
    └── a1-3
```

a1 が a からしか呼ばれず、配下の処理も a1 の内部に閉じていれば、a1 全体を一つの組み換え単位として扱える。配下の依存関係が複雑でもよいが、その複雑さは変更コストになる。a1-1 などを単独で組み換えられるとは限らない。

## 組み換えの条件

入出力の契約（結果、エラー、副作用など）を維持すること。契約を対象とするテストは内部実装に依存させない。契約が維持されれば、内部を交換しても呼び出し元や既存のテストコードを変更せずに済む。

## 評価基準

- **組み換え単位**：変更時にまとめて扱う必要がある範囲。
- **組み換えコスト**：その範囲の内部依存を変更・検証する負担。

組み換え単位を小さくすること自体にも分割・境界管理のコストがあるため、細分化は目的ではなく手段とする。この原則に適合しない設計まで無理に当てはめない。
